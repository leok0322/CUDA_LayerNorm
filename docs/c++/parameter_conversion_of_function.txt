================================================================================
              函数参数的 const 修饰：声明与定义分离时的行为差异
================================================================================

--------------------------------------------------------------------------------
一、Clang-Tidy 警告含义
--------------------------------------------------------------------------------

警告信息：
  Parameter 'totalRow' is const-qualified in the function declaration;
  const-qualification of parameters only has an effect in function definitions

含义：
  const 修饰值参数时，写在函数声明里没有意义，只在函数定义里才有实际效果。

--------------------------------------------------------------------------------
二、根本原因
--------------------------------------------------------------------------------

值传递的参数，调用者传入的是一份副本，函数内部如何操作这份副本，
对调用者没有任何影响。因此：

  声明里的 const：对调用者没有任何约束，编译器忽略它，只是噪音
  定义里的 const：有意义，防止函数体内意外修改参数的副本

示例：

  // 声明（.cuh / .h）
  void run_LayerNorm_kernel_base(const uint totalRow, const uint totalCol, ...);
  //                              ↑ 这里的 const 对调用者毫无意义，触发 Clang-Tidy 警告

  // 定义（.cu / .cpp）
  void run_LayerNorm_kernel_base(const uint totalRow, const uint totalCol, ...) {
      // 这里的 const 有意义：告诉编译器函数体内不会修改 totalRow
      // totalRow = 0;  ← 编译报错
  }

--------------------------------------------------------------------------------
三、与指针 / 引用参数的对比
--------------------------------------------------------------------------------

指针和引用的 const 在声明里有意义，调用者需要知道函数是否会修改所指内容：

  void foo(const uint* p);    // 承诺不通过 p 修改所指内容，调用者可传 const 指针
  void bar(const uint& ref);  // 承诺不修改引用的对象，调用者可传 const 变量

值参数的 const 在声明里没有意义，Clang-Tidy 会警告：

  void baz(const uint val);   // 只影响函数内部的副本，调用者无感知，警告

--------------------------------------------------------------------------------
四、修复方式
--------------------------------------------------------------------------------

声明去掉顶层 const，定义里按需保留：

  // runner.cuh（声明）—— 去掉 const
  void run_LayerNorm_kernel_base(uint totalRow, uint totalCol, float* A, float* out);

  // runner.cu（定义）—— 按需保留
  void run_LayerNorm_kernel_base(const uint totalRow, const uint totalCol,
                                  float* A, float* out) {
      // ...
  }

C++ 标准允许声明和定义在值参数的顶层 const 上不一致，两者签名不冲突。

--------------------------------------------------------------------------------
五、声明与定义合一时 const 值参数有意义
--------------------------------------------------------------------------------

当声明和定义合一（直接在头文件里写函数体，如 inline 函数或 .cuh 文件中的函数）时，
const 值参数有实际意义，Clang-Tidy 也不会再触发警告：

  // 声明和定义合一（如 .cuh 中的 inline 函数）
  inline void run_LayerNorm_kernel_base(const uint totalRow, const uint totalCol,
                                         float* A, float* out) {
      // const 在这里有效：编译器阻止函数体内意外修改 totalRow / totalCol
      // totalRow = 0;  ← 编译报错
  }

此时没有单独的声明，Clang-Tidy 不会警告。

--------------------------------------------------------------------------------
六、触发警告的场景总结
--------------------------------------------------------------------------------

  场景                              const 值参数是否有意义   是否触发警告
  ──────────────────────────────────────────────────────────────────────
  声明和定义分离，const 在声明里    否                        是
  声明和定义分离，const 在定义里    是                        否
  声明和定义合一，const 在函数体里  是                        否
