================================================================================
     Kernel 2 vs Kernel 4：Double Warp Reduction vs Welford 性能对比
     kernel 2 = LayerNorm_kernel_double_warp_reduction        （两遍读 GMEM）
     kernel 4 = LayerNorm_kernel_welford_double_warp_reduction（单遍读 GMEM）
================================================================================

--------------------------------------------------------------------------------
一、两个 kernel 的结构差异
--------------------------------------------------------------------------------

Kernel 2（两遍读 GMEM）
  Pass 1：遍历行，累加 sumX → warp 规约 → 得到 mean
  Pass 2：再次遍历行，累加 Σ(xᵢ-mean)² → warp 规约 → 得到 var → 归一化写出
  Warp 规约次数：2 次（mean 一次，var 一次）；每次交换 1 个变量

Kernel 4（单遍读 GMEM，Welford 算法）
  Pass 1：遍历行，每次读 4 个元素，用 Welford 批量合并公式同时维护 mean 和 M2
           → warp 规约 → 得到 mean 和 var → 归一化写出
  Warp 规约次数：1 次；但每次同时交换 3 个变量（count, mean, var）

关键差异：kernel 4 将两遍 GMEM 读合并为一遍，
          代价是内层循环计算量大幅增加，且 warp 规约变量数翻倍。

--------------------------------------------------------------------------------
二、内层循环计算量对比
--------------------------------------------------------------------------------

Kernel 2 Pass 1（只计算 mean），每 4 个元素：
  ┌──────────────────────────────────────────────────────┐
  │  sumX += v.x + v.y + v.z + v.w                      │
  │  操作：4 次 float 加法                                │
  │  除法：0 次                                           │
  │  指令数/元素：~1                                       │
  └──────────────────────────────────────────────────────┘

Kernel 4 Welford 内层循环，每 4 个元素：
  ┌──────────────────────────────────────────────────────┐
  │  1. rowMean += x+y+z+w; rowMean /= 4                 │  4 加 + 1 乘（÷4→×0.25）
  │  2. M2_B = Σ(xi - rowMean)²                          │  4 减 + 4 乘 + 4 加
  │  3. meanDiff = rowMean - rowMeanOld                   │  1 减
  │  4. rowMean = rowMeanOld + delta*4/count              │  1 乘 + 1 变量除法 ← 慢
  │  5. rowVar += rowVarOld + delta²*(cnt-4)*4/cnt        │  3 乘 + 1 变量除法 + 2 加 ← 慢
  │  6. 寄存器搬运 + 清零                                  │  4 赋值
  │  操作：~28 条指令，含 2 次变量除法（÷count，~25–30 cycle）│
  └──────────────────────────────────────────────────────┘

Warp 规约对比：
  Kernel 2：mean 规约（5×shfl×1变量）+ var 规约（5×shfl×1变量）= 10 次 shfl
  Kernel 4：单次规约（5×shfl×3变量）= 15 次 shfl，规约代价增加 50%

说明：÷4 由编译器优化为 ×0.25（1 cycle）；÷count 是变量除法，
      GPU float 除法延迟 ~25–30 个时钟周期，无法被优化消除。

--------------------------------------------------------------------------------
三、全局内存访问对比（以 N×C 矩阵为例）
--------------------------------------------------------------------------------

Kernel 2：
  Pass 1 读 A：N × C × 4 字节
  Pass 2 读 A：N × C × 4 字节
  写 out  ：N × C × 4 字节
  ─────────────────────────────
  总 GMEM：3 × N × C × 4 字节

Kernel 4：
  Pass 1 读 A：N × C × 4 字节（mean + var 同时计算）
  写 out  ：N × C × 4 字节
  ─────────────────────────────
  总 GMEM：2 × N × C × 4 字节

减少量：N × C × 4 字节（减少 33% 的 GMEM 访问）

对于 N=4096, C=4096：
  Kernel 2 GMEM：3 × 4096 × 4096 × 4 ≈ 192 MB
  Kernel 4 GMEM：2 × 4096 × 4096 × 4 ≈ 128 MB
  节省约 64 MB

--------------------------------------------------------------------------------
五、性能差异的详细分析
--------------------------------------------------------------------------------

5.1 C = 4096 时两者持平的原因
──────────────────────────────
当 C 足够大时，kernel 进入内存带宽瓶颈区域：
  - 每个元素算术强度约 0.5 FLOP/byte，远低于 roofline 计算峰值
  - GPU 执行时间主要由 GMEM 传输决定
  - Kernel 4 减少 33% 的 GMEM 读取，与其更重的 Welford 计算开销相互抵消
  - 净结果：C=4096 时两者几乎相同

5.2 N = 128 时 kernel 4 大幅领先的原因
────────────────────────────────────────
只有 128 个 block，GPU 无法被充分饱和（典型 GPU 有 80–108 个 SM）：
  - 每个 SM 约跑 1 个 block，无法靠多 warp 并发隐藏延迟
  - 此时瓶颈从带宽转为每个 block 的执行延迟
  - Kernel 2 每个 block 执行两遍内层循环（mean + var），总延迟约为 kernel 4 的 2 倍
  - Kernel 4 只执行一遍循环 → 每 block 完成更快 → 总时间更短

  例：128 × 1024，kernel 2 = 0.000156s，kernel 4 = 0.000093s，快 40%

  N=128, C=4096 反转（K4 慢 10%）：
    - 数据量 128×4096×4 = 2MB，超出 L2 cache
    - 每线程需多次迭代，Welford 每迭代 2 次变量除法（~25–30 cycle）累计开销变重
    - 单遍优势被 Welford 计算代价抵消

5.3 N ≥ 256，C < 4096 时 kernel 2 领先的原因
──────────────────────────────────────────────
GPU block 数充足，带宽和算术同时成为竞争因素：

① Warp 规约代价增加
   Kernel 4 的单次规约需交换 3 个变量（count, mean, var），共 15 次 shfl；
   Kernel 2 的两次规约各 1 个变量，共 10 次 shfl。
   当 C 小（每线程处理元素少），规约占总时间比例高，kernel 4 的规约代价劣势放大。

② 寄存器压力降低 occupancy
   Kernel 4 同时持有更多活跃寄存器（rowMean, rowMeanOld, rowVar, rowVarOld,
   elementDiff, meanDiff, count, countXor, rowMeanXor, rowVarXor 等）；
   寄存器增多 → 每 SM 可并发的 warp 数减少 → 内存延迟隐藏能力下降。

③ 内层 Welford 计算代价
   每 4 个元素 ~28 条指令 vs kernel 2 两遍合计 ~16 条，含 2 次变量除法（高延迟）。
   当 C 小（循环迭代少），这些额外指令占时间比重更大。

5.4 综合：三区域模型
─────────────────────
  ┌───────────────────┬────────────────────────────┬──────────────────────┐
  │ 区域              │ 主导因素                    │ 结果                 │
  ├───────────────────┼────────────────────────────┼──────────────────────┤
  │ N=128，C≤2048     │ 每 block 延迟（block 数不足）│ K4 领先（单遍优势）  │
  │ N≥256，C<4096     │ 规约代价+寄存器压力+除法延迟 │ K2 领先              │
  │ 任意 N，C=4096    │ GMEM 带宽瓶颈               │ 持平（相互抵消）      │
  └───────────────────┴────────────────────────────┴──────────────────────┘

--------------------------------------------------------------------------------
六、结论与启示
--------------------------------------------------------------------------------

1. "减少 GMEM 读取次数一定更快"的假设并不总成立。
   Welford 的收益（33% 读取减少）只在 C 足够大使 kernel 进入带宽瓶颈时才能体现；
   在此之前，Welford 的额外计算代价（28 指令/元素、变量除法、更多 shfl）反而更慢。

2. 对于 LLM 中典型的 LayerNorm（hidden_dim = 1024–4096，batch 较大），
   kernel 2 和 kernel 4 在 C=4096 时性能相当，在 C=1024 时 kernel 2 更优。
   Welford 的数值精度优势在 float32 激活值场景下也无实际意义。

3. 若想同时获得"单遍读取"和"内层循环简单"的优势，应改用 sumX + sumX² 方案：
     sumX  += v.x + v.y + v.z + v.w       // 4 次加法/元素，无除法
     sumX2 += v.x²+ v.y²+ v.z²+ v.w²     // 4 次乘加/元素，无除法
     // 归约后：mean = sumX/C,  var = sumX2/C - mean²
   代价是轻微精度损失（通常对神经网络可接受）；
   这是 PyTorch 早期 LayerNorm kernel 和 apex 的实际选择。
