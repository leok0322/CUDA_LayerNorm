================================================================================
          Kernel 2 vs Kernel 3：Double Warp Reduction vs Welford 性能对比
================================================================================

--------------------------------------------------------------------------------
一、两个 kernel 的结构差异
--------------------------------------------------------------------------------

Kernel 2（双轮 warp 规约，两遍读 GMEM）
  Pass 1：遍历行，累加 sumX → warp 规约 → 得到 mean
  Pass 2：再次遍历行，累加 Σ(xᵢ-mean)² → warp 规约 → 得到 var → 归一化写出

Kernel 3（Welford 单遍，一遍读 GMEM）
  Pass 1：遍历行，每次读 4 个元素，用 Welford 批量合并公式同时维护 mean 和 M2
           → warp 规约 → 得到 mean 和 var → 归一化写出

关键差异：kernel 3 将两遍 GMEM 读合并为一遍，代价是内层循环计算量大幅增加。

--------------------------------------------------------------------------------
二、内层循环计算量对比
--------------------------------------------------------------------------------

Kernel 2 Pass 1（只计算 mean），每 4 个元素：
  ┌─────────────────────────────────────────────┐
  │  sumX += v.x + v.y + v.z + v.w             │
  │  操作：4 次 float 加法                       │
  │  除法：0 次                                  │
  │  指令数/元素：~1                              │
  └─────────────────────────────────────────────┘

Kernel 3 Welford 内层循环，每 4 个元素：
  ┌─────────────────────────────────────────────┐
  │  1. rowMean += x+y+z+w; rowMean /= 4        │  4 加 + 1 乘（÷4 → ×0.25）
  │  2. M2_B = Σ(xi - rowMean)²                 │  4 减 + 4 乘 + 4 加
  │  3. meanDiff = rowMean - rowMeanOld          │  1 减
  │  4. rowMean = rowMeanOld + delta*4/count     │  1 乘 + 1 变量除法 ← 慢
  │  5. rowVar += rowVarOld + delta²*(cnt-4)*4/cnt │ 3 乘 + 1 变量除法 + 2 加 ← 慢
  │  6. 寄存器搬运 + 清零                         │  4 赋值
  │  操作：~28 条指令                              │
  │  变量除法：2 次（÷count，无法优化为乘法）       │
  │  指令数/元素：~7                               │
  └─────────────────────────────────────────────┘

说明：÷4 由编译器优化为 ×0.25（1 cycle）；÷count 是变量除法，
      GPU float 除法延迟 ~25–30 个时钟周期，无法被优化消除。

--------------------------------------------------------------------------------
三、全局内存访问对比（以 N×C 矩阵为例）
--------------------------------------------------------------------------------

Kernel 2：
  Pass 1 读 A：N × C × 4 字节
  Pass 2 读 A：N × C × 4 字节
  写 out  ：N × C × 4 字节
  ─────────────────────────────
  总 GMEM：3 × N × C × 4 字节

Kernel 3：
  Pass 1 读 A：N × C × 4 字节（mean + var 同时计算）
  写 out  ：N × C × 4 字节
  ─────────────────────────────
  总 GMEM：2 × N × C × 4 字节

减少量：N × C × 4 字节（减少 33% 的 GMEM 访问）

对于 N=4096, C=4096：
  Kernel 2 GMEM：3 × 4096 × 4096 × 4 ≈ 192 MB
  Kernel 3 GMEM：2 × 4096 × 4096 × 4 ≈ 128 MB
  节省约 64 MB

--------------------------------------------------------------------------------
五、性能差异的详细分析
--------------------------------------------------------------------------------

5.1 GMEM 减少带来的收益
────────────────────────
LayerNorm kernel 是典型的内存带宽受限（memory-bandwidth bound）操作：
  - 每个元素的算术强度（arithmetic intensity）约为 8 FLOP / 16 byte ≈ 0.5 FLOP/byte
  - RTX/A100 的 roofline 模型显示该点远在计算峰值以下，瓶颈在带宽

因此减少 33% 的 GMEM 读取，理论上应有 ~33% × (2/3) ≈ 22% 的加速
（仅针对读取部分；写出不变）。

5.2 Welford 内层循环消耗部分收益
──────────────────────────────────
每次迭代的两次变量除法（÷count）引入额外延迟：
  - 变量除法延迟 ~25–30 cycle，而 float 加法仅 ~4 cycle
  - 对于 C=4096，BLOCK_SIZE=1024，每线程处理 1 个 float4（1 次迭代），
    只产生 2 次除法，绝对成本不高
  - 对于 C=128，BLOCK_SIZE=1024，大部分线程什么都不处理（count=0），
    Welford 的设计收益几乎消失，反而有更多无用指令

5.3 更长的指令依赖链
─────────────────────
Welford 内层循环中，每次迭代的 rowMean 和 rowVar 都依赖上一次迭代的
rowMeanOld / rowVarOld（串行依赖链），GPU 指令调度器难以乱序执行。
Kernel 2 的 sumX 累加也是串行，但每次只做 1 条加法指令，依赖链短得多。

5.4 寄存器压力
──────────────
Kernel 3 同时持有更多活跃寄存器（rowMean, rowMeanOld, rowVar, rowVarOld,
elementDiff, meanDiff, count, countXor, rowMeanXor, rowVarXor + 其他）：
  → 更低的 occupancy（每个 SM 能并发的 warp 数减少）
  → 内存延迟的隐藏能力下降

Kernel 2 分两遍，每遍寄存器需求更少。

5.5 综合：收益与代价的抵消
───────────────────────────
  GMEM 减少 33%  →  理论加速上限 ~22%（仅读取部分）
  Welford 计算代价  →  损耗约 17–20%
  ─────────────────────────────────────────────────
  实际净提升        ~2–5%（与大矩阵测量数据吻合）

  理论 22% 与实测 5% 之间的巨大差距（~17%）来自：
    ① 变量除法延迟：每线程 2 次 ÷count，每次 ~25–30 cycle
    ② 更多指令：内层循环 ~28 条 vs kernel 2 pass 1 的 ~4 条
    ③ 更高寄存器压力：occupancy 下降，内存延迟隐藏能力变弱
    ④ 更长依赖链：rowMean/rowVar 跨迭代串行依赖，ILP 降低

--------------------------------------------------------------------------------
六、结论与启示
--------------------------------------------------------------------------------

1. Welford 的精度优势（避免 Σx² - N·μ² 的灾难性消除）在 LayerNorm 的
   实际参数范围内收益有限，float32 对神经网络激活值足够精确。

2. 更高性能的单遍方案是累加 sumX 和 sumX²，循环内无除法，内层循环
   与 kernel 2 pass 1 等价，然后在归约后统一计算 mean 和 var：
     mean = sumX  / totalCol
     var  = sumX2 / totalCol - mean * mean
   代价：轻微精度损失（通常可接受）；收益：~33% 加速且内层循环最简。

3. 对于生产级 kernel（如 FlashNorm、apex LayerNorm），通常选择
   sumX + sumX² 方案，而非 Welford，原因正是本文的分析：
   Welford 的精度优势无法弥补其在 GPU 上的计算开销。
