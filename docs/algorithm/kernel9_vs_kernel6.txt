--------------------------------------------------------------------------------
一、kernel 9 实现解析
--------------------------------------------------------------------------------

1.1 block 维度设计
──────────────────
  block：dim3(WARP_SIZE=32, block_y)
    threadIdx.x：warp 内 lane，负责列方向（0–31）
    threadIdx.y：warp 编号，负责行方向（不同 token）

  每个 warp（threadIdx.y 固定）独立处理一行，x 维度固定为 32 = 一个硬件 warp。

1.2 列覆盖：步进循环
────────────────────
  x 维度只有 32 条线程，通过步进循环覆盖所有 totalCol 列：

    for (int c = threadIdx.x * x128::size;   // 起始：lane × 4
             c < totalCol;
             c += WARP_SIZE * x128::size) {  // 步长：32 × 4 = 128
        x128 in_data = load128cs(A + c);     // 一次加载 4 × float = 128-bit
        ...
    }

  每轮 32 条线程合计覆盖 128 列，循环 totalCol/128 轮即可覆盖全部列。
  无论 totalCol 多大，32 条线程在每轮中全部满载，零空转。

1.3 weight/bias 全 block 协作加载
──────────────────────────────────
  所有 block_y × 32 条线程共同将 weight/bias 加载到 shared memory：

    int sidx = (threadIdx.x + WARP_SIZE * threadIdx.y) * x128::size;
    for (int i = sidx; i < totalCol; i += blockDim.y * WARP_SIZE * x128::size) {
        s_weight[i / x128::size] = load128(weight + i);
        s_bias[i / x128::size]   = load128(bias + i);
    }
    __syncthreads();

  步长 = blockDim.y × 128，每轮 block_y 个 warp × 128 列/warp = block_y × 128 列。
  全员参与将加载带宽压力均摊为单 warp 加载的 block_y 倍。

1.4 规约：单级 warp 规约
────────────────────────
  x = 32 恰为一个硬件 warp，直接调用 warpReduceSum（__shfl_xor_sync 蝶形，5 轮）：

    sum = warpReduceSum(sum);   // 一级即得全局和

  // warpReduceSum 而非 cg::reduce 的原因：
  //   内层循环用 x128（4×float 结构体）展开累加到标量 sum，
  //   cg::reduce 只支持标量类型，无法直接作用于 x128；
  //   必须先手动展开再做标量规约。

1.5 向量化与内联 PTX
────────────────────
  x128 = 4×float，通过内联 PTX 实现 streaming 128-bit 加载/存储：

    // 加载：ld.global.cs.v4.f32，.cs 表示 cache streaming（L1 快速逐出）
    asm volatile("ld.global.cs.v4.f32 {%0,%1,%2,%3}, [%4];"
                 : "=f"(x.data[0]), ..., "=f"(x.data[3])
                 : "l"(addr));

    // 存储：st.global.cs.v4.f32，写入后 L1 快速逐出，减少 cache 污染
    asm volatile("st.global.cs.v4.f32 [%0], {%1,%2,%3,%4};"
                 : : "l"(addr), "f"(val.data[0]), ..., "f"(val.data[3]));

1.6 行索引
──────────
  grid 一维（blockIdx.x）：
    int idx = blockIdx.x * blockDim.y + threadIdx.y;

二、与 kernel 6 的异同
--------------------------------------------------------------------------------

  ┌───────────────────────┬──────────────────────────────┬──────────────────────────────┐
  │                       │ kernel 6                     │ kernel 9                     │
  ├───────────────────────┼──────────────────────────────┼──────────────────────────────┤
  │ block x 维度          │ BSX_SMEM（默认 256）          │ 32（固定，= 1 个 warp）       │
  │ block y 维度          │ BSY_SMEM（默认 4）            │ block_y（可调）               │
  │ 规约层数              │ 二级                          │ 一级                          │
  │                       │ warp → SMEM → warp 0         │ 单 warp（warpReduceSum）       │
  │ weight/bias 加载      │ 仅 threadIdx.y==0 的 warp     │ 全 block 协作加载             │
  │ 输入行缓存（SMEM）    │ smemA，stride-5 布局          │ s_in，自然对齐                │
  │ SMEM 布局步长         │ stride-5（避免 bank conflict）│ 无 padding（x128 天然对齐）   │
  │ 向量化方式            │ scalar_t4 + reinterpret_cast  │ x128 + 内联 PTX              │
  │ 行索引方向            │ blockIdx.y（二维 grid）       │ blockIdx.x（一维 grid）       │
  └───────────────────────┴──────────────────────────────┴──────────────────────────────┘

  相同点：
    - 每个 warp 负责一行
    - 将输入行 A 缓存到 SMEM，variance 和归一化从 SMEM 读（避免二次访问全局内存）
    - 将 weight/bias 缓存到 SMEM，多行共享同一份副本
    - 使用 __stcs（streaming store）写出 mean/rstd/out

  二级规约的原因：
    kernel 6 x=256 → 每行由 8 个 warp 共同处理，warp 内规约后仍有 8 个局部和，
    必须借助 SMEM 中转做第二级规约：

      if (threadIDX % 32 == 0)
          reduction[threadIdx.y][threadIDX / 32] = rowMean;  // 8 个局部和写入 SMEM
      __syncthreads();
      if (threadIDX < 32)
          rowMean = threadIDX < warp0threadNum ? reduction[...] : 0;
      // warp 0 再做一次规约

    kernel 9 x=32 → 每行恰好一个 warp，单次 warpReduceSum 即得全局和，
    无需 SMEM 中转，也无需额外 __syncthreads()。

三、性能数据对比（GFLOPS，sm_86）
--------------------------------------------------------------------------------

  ┌──────────────┬──────────┬──────────┬────────────────────┐
  │ (rows, cols) │ kernel 6 │ kernel 9 │ 说明               │
  ├──────────────┼──────────┼──────────┼────────────────────┤
  │ 4096,  128   │   96.2   │  270.9   │ K9 +182%           │
  │ 1024,  128   │   52.0   │  138.7   │ K9 +167%           │
  │ 2048,  128   │   85.4   │  150.9   │ K9  +77%           │
  │  128,  128   │   11.0   │   20.1   │ K9  +83%           │
  │ 2048,  256   │  143.7   │  260.1   │ K9  +81%           │
  │ 4096,  256   │  170.6   │  237.0   │ K9  +39%           │
  │ 4096,  512   │  251.9   │  252.9   │ 持平               │
  │ 4096, 1024   │  261.1   │  257.1   │ 持平               │
  │ 2048, 2048   │  258.9   │  257.8   │ 持平               │
  │ 4096, 4096   │  266.3   │  243.3   │ K6 略好            │
  └──────────────┴──────────┴──────────┴────────────────────┘

  规律：
    totalCol ≤ 512  ：kernel 9 显著领先（最高 +182%）
    totalCol ≈ 1024 ：接近持平
    totalCol ≥ 2048 ：持平或 kernel 6 略好

--------------------------------------------------------------------------------
四、小 totalCol 时 kernel 9 领先的根本原因
--------------------------------------------------------------------------------

  kernel 6 在小 totalCol 时大量线程空转：

    BSX=256，列循环：for (col = threadIDX; col < totalCol/4; col += 256)

    totalCol=128 时，totalCol/4=32，只有 thread 0–31（第一个 warp）进入循环，
    其余 224 条线程立即空转，warp 利用率仅 32/256 = 12.5%。

    这 7 个空 warp 仍然：
      - 占用 SM 的 warp slot 和寄存器
      - 参与 __syncthreads()（拖慢所有人）
      - 触发完整的二级规约流程（即使贡献值全为 0）

  kernel 9 始终 100% 利用 warp：

    BSX=32，列循环步长 128，totalCol=128 时每条线程恰好处理 4 列，
    32 条线程全部满载，一轮循环覆盖全部列，
    单级 warpReduceSum 结束，无 SMEM sync 开销。

  大 totalCol 时两者趋于持平：
    totalCol 大时 kernel 6 的 256 条线程全部有工作，空转消失；
    但二级规约开销、weight/bias 只由一个 warp 加载的串行瓶颈逐渐显现，
    抵消了多 warp 并行带来的列覆盖收益。

--------------------------------------------------------------------------------
五、结论
--------------------------------------------------------------------------------

  kernel 9 是 kernel 6 的简化与优化版本：
    - 将 x 维度从 256 缩减到 32，彻底消除小 totalCol 时的线程空转
    - 二级规约退化为一级，减少同步开销
    - 全 block 协作加载 weight/bias，均摊加载带宽

  适用场景：
    totalCol 较小（≤ 512）时，kernel 9 有显著优势；
    totalCol 较大（≥ 2048）时，两者性能接近，kernel 6 因多 warp 并行略有优势。
