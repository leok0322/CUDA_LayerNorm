--------------------------------------------------------------------------------
一、算法概述
--------------------------------------------------------------------------------

Layer Normalization（层归一化）是深度学习中的一种归一化技术，由 Jimmy Lei Ba 等
人于 2016 年提出，最初用于解决循环神经网络（RNN）中 Batch Normalization 不适用的
问题。

与 Batch Normalization 沿 batch 维度统计不同，LayerNorm 对单个样本的特征维度
（即最后 D 个维度）独立计算均值和方差，因此不依赖 batch size，天然适合：
  - 序列模型（RNN、LSTM）
  - Transformer / 自注意力模块
  - 小 batch 或在线学习场景

为什么需要归一化？
  深度模型（尤其是 Transformer）有数十乃至上百层，每层的矩阵乘法和激活函数都会
  改变输出的分布（均值和方差漂移）。随着层数加深，激活值可能持续放大或缩小，
  导致梯度爆炸或消失，训练无法收敛。归一化的核心目的：

  1. 稳定激活值分布：强制每层输入保持零均值、单位方差，让梯度信号稳定地向前/
     向后传播，不随层数积累而发散。

  2. 平坦化优化景观：归一化使损失曲面更光滑，对学习率选择不那么敏感，相同的
     超参数在更深的网络中依然有效。

  3. γ/β 恢复表达能力：强制零均值单位方差会压缩模型的表示空间。可学习的 γ
     （缩放）和 β（偏移）让网络自行决定每层需要的分布——本质上是把"选择分布"
     这件事交给模型学习，而不是强制固定。初始化 γ=1, β=0 等价于"先归一化，
     再按需调整"，训练初期等同于标准归一化，随后逐渐偏离以适应任务需求。

核心流程（前向传播）：
  1. 计算输入在归一化维度上的均值 μ
  2. 计算输入在归一化维度上的方差 σ²
  3. 对输入做零均值单位方差归一化，得到 x̂
  4. 施加可学习的仿射变换：y = γ ⊙ x̂ + β

γ（weight/scale）和 β（bias）是与特征维度等长的可学习参数，初始化为 γ=1, β=0。

--------------------------------------------------------------------------------
二、数学原理
--------------------------------------------------------------------------------

2.1 符号定义
------------
  x ∈ R^{B×...×D}    输入张量，D 为归一化维度（normalized_shape）
  H = D               归一化维度的元素总数（若 normalized_shape 多维则 H = ∏Dᵢ）
  ε                   数值稳定项（典型值 1e-5）
  γ, β ∈ R^D         可学习的 scale 与 bias 参数

2.2 前向传播（Forward Pass）
----------------------------
对输入向量 x（已展平最后若干维，长度 H）：

  (1) 均值：
        μ = (1/H) · Σᵢ xᵢ

  (2) 方差：
        σ² = (1/H) · Σᵢ (xᵢ - μ)²

  (3) 归一化：
        x̂ᵢ = (xᵢ - μ) / sqrt(σ² + ε)

  (4) 仿射变换：
        yᵢ = γᵢ · x̂ᵢ + βᵢ

其中 sqrt(σ² + ε) 有时记作 rstd（reciprocal standard deviation），实现中常存储
其倒数 rstd = 1 / sqrt(σ² + ε) 以减少除法运算。

2.3 反向传播（Backward Pass）
------------------------------
设损失为 L，已知上游梯度 dy = ∂L/∂y，推导 dx、dγ、dβ。

  (a) 参数梯度（对所有样本求和）：
        dγᵢ = Σ_samples (dyᵢ · x̂ᵢ)
        dβᵢ = Σ_samples dyᵢ

  (b) 输入梯度（对单个样本）：
      令 a = dy ⊙ γ，需从 dx̂ 反推 dx。

      由链式法则展开（经过均值和方差的依赖关系）：

        dx̂ᵢ = aᵢ

        dσ² = Σᵢ dx̂ᵢ · (xᵢ - μ) · (-1/2) · (σ² + ε)^{-3/2}
             = (-1/2) · rstd³ · Σᵢ aᵢ · (xᵢ - μ)

        dμ  = Σᵢ dx̂ᵢ · (-rstd)  +  dσ² · Σᵢ (-2(xᵢ - μ)) / H
             = -rstd · Σᵢ aᵢ  +  dσ² · 0          （因 Σ(xᵢ-μ)=0）
             = -rstd · Σᵢ aᵢ

        dxᵢ = dx̂ᵢ · rstd  +  dσ² · 2(xᵢ - μ)/H  +  dμ/H

      整理为紧凑形式（令 c̄ = Σaᵢ, d̄ = Σaᵢ·x̂ᵢ）：

        dxᵢ = rstd · [ aᵢ  -  (1/H)·c̄  -  x̂ᵢ·(1/H)·d̄ ]

      该式无需显式存储 dσ² 和 dμ，只需两个标量 c̄ 和 d̄ 即可完成计算。

2.4 数值稳定性分析
------------------
  - ε 防止方差为零时的除以零错误。
  - 实现中常先用 float32/float64 累加统计量，再转回低精度，以缓解 half 精度下
    的数值精度损失。
  - Welford 在线算法可在单次遍历中同时计算均值和无偏方差，避免两遍扫描，适合
    流式/内存受限场景。

2.5 Welford 在线算法（单遍计算均值与方差）
------------------------------------------

── 2.5.1 朴素公式的数值问题：灾难性抵消 ────────────────────────────────────────

展开方差公式：
    σ² = (1/N)·Σxᵢ²  −  μ²

当均值远大于标准差时（如 x ≈ 10⁶，σ ≈ 1）：
    Σxᵢ²  ≈ N × 10¹²
    N·μ²   ≈ N × 10¹²
    差值   ≈ N·σ² ≈ N

两个量级为 10¹² 的浮点数相减，结果量级为 1——float32 约有 7 位有效数字，
此时有效位数全部损失，计算结果可能完全错误。这种现象称为"灾难性抵消"。

── 2.5.2 单元素 Welford 更新公式的代数推导 ──────────────────────────────────────

状态量（处理前 k 个元素后）：
    mean_k  : 前 k 个元素的均值
    M2_k    : 偏差平方和 = Σᵢ₌₁ᵏ (xᵢ − mean_k)²

加入第 k+1 个元素 x 时，令：
    δ  = x − mean_k          （新元素与旧均值的差）
    δ' = x − mean_{k+1}      （新元素与新均值的差）

均值更新（精确）：
    mean_{k+1} = (k·mean_k + x) / (k+1)
               = mean_k + δ/(k+1)

由此推导 δ'：
    δ' = x − mean_{k+1}
       = x − mean_k − δ/(k+1)
       = δ·k/(k+1)

M2 更新推导：
    M2_{k+1} = Σᵢ₌₁^{k+1} (xᵢ − mean_{k+1})²

    对前 k 项（令 eᵢ = xᵢ − mean_k）：
      Σᵢ₌₁ᵏ (eᵢ − δ/(k+1))²
    = Σeᵢ²  − 2·δ/(k+1)·Σeᵢ  +  k·(δ/(k+1))²
    = M2_k  − 0               +  k·δ²/(k+1)²      ← Σeᵢ = 0（均值定义）

    对第 k+1 项：
      (x − mean_{k+1})² = (δ')² = k²·δ²/(k+1)²

    合并：
      M2_{k+1} = M2_k + k·δ²/(k+1)² + k²·δ²/(k+1)²
               = M2_k + δ²·k·(1+k)/(k+1)²
               = M2_k + δ²·k/(k+1)
               = M2_k + δ·δ'              ← 因为 δ·δ' = δ·(δ·k/(k+1)) = δ²·k/(k+1)

结论：M2_{k+1} = M2_k + δ·δ' 是代数恒等式，无任何近似。

── 2.5.3 为何数值稳定 ───────────────────────────────────────────────────────────

每步累加的是 δ·δ'——新元素与当前均值的偏差之积。
当元素值很大但方差很小时，δ 和 δ' 的量级接近 σ（而非 x 本身），
直接累加小量，完全避免了"两个大数相减"：

    朴素公式：  Σxᵢ²  −  N·μ²       大数 − 大数，精度损失 ∝ μ²/σ²
    Welford ：  Σ δᵢ·δᵢ'              每项量级 ≈ σ²，无抵消

── 2.5.4 单元素更新规则（汇总） ────────────────────────────────────────────────

    count  += 1
    delta   = x − mean          // δ：与旧均值的差
    mean   += delta / count     // 均值增量更新
    delta2  = x − mean          // δ'：与新均值的差（使用更新后的 mean）
    M2     += delta * delta2    // 偏差平方和累计

    处理完所有 H 个元素后：
      μ  = mean
      σ² = M2 / H               // 有偏方差，LayerNorm 使用此形式

── 2.5.5 批量合并公式（新增一批元素）──────────────────────────────────────────

当新增的是一批元素而非单个元素时，可将"当前状态"与"新批次统计量"作为两组
合并（Chan et al., 1979 并行算法）。单元素更新是 n_b=1 时的特例。

已知两组统计量：
    组 a：n_a 个元素，mean_a，M2_a = Σᵢ∈a (xᵢ − mean_a)²
    组 b：n_b 个元素，mean_b，M2_b = Σⱼ∈b (xⱼ − mean_b)²

合并均值（精确）：
    n_ab    = n_a + n_b
    δ       = mean_b − mean_a
    mean_ab = mean_a + δ·n_b / n_ab

合并 M2 推导：
    M2_ab = Σᵢ∈a (xᵢ − mean_ab)² + Σⱼ∈b (xⱼ − mean_ab)²

    对组 a（令 eᵢ = xᵢ − mean_a）：
      Σᵢ∈a (eᵢ + mean_a − mean_ab)²
    = M2_a + 2(mean_a − mean_ab)·Σᵢ∈a eᵢ + n_a·(mean_a − mean_ab)²
    = M2_a + 0 + n_a·(δ·n_b/n_ab)²           ← mean_a − mean_ab = −δ·n_b/n_ab

    对组 b（令 fⱼ = xⱼ − mean_b）：
      Σⱼ∈b (fⱼ + mean_b − mean_ab)²
    = M2_b + n_b·(δ·n_a/n_ab)²               ← mean_b − mean_ab = δ·n_a/n_ab

    合并：
      M2_ab = M2_a + M2_b + n_a·δ²·n_b²/n_ab² + n_b·δ²·n_a²/n_ab²
            = M2_a + M2_b + δ²·n_a·n_b·(n_a + n_b)/n_ab²
            = M2_a + M2_b + δ²·n_a·n_b / n_ab

最终批量合并公式：
    n_ab    = n_a + n_b
    δ       = mean_b − mean_a
    mean_ab = mean_a + δ · n_b / n_ab
    M2_ab   = M2_a + M2_b + δ² · n_a · n_b / n_ab
    σ²      = M2_ab / n_ab

── 2.5.6 GPU 实现示意 ───────────────────────────────────────────────────────────

每个线程用单元素 Welford 处理自己负责的多个元素，
归约时（warp shuffle / shared memory）用批量合并公式：

    struct WelfordState { float mean, M2; int count; };

    __device__ WelfordState merge(WelfordState a, WelfordState b) {
        int   n   = a.count + b.count;
        float d   = b.mean - a.mean;
        return { a.mean + d * b.count / n,
                 a.M2 + b.M2 + d * d * a.count * b.count / n,
                 n };
    }

    // warp 归约：每次 shuffle 交换对面线程的状态，调用 merge 合并
    for (int offset = 16; offset >= 1; offset >>= 1) {
        WelfordState peer = {
            __shfl_xor_sync(0xffffffff, state.mean,  offset),
            __shfl_xor_sync(0xffffffff, state.M2,    offset),
            __shfl_xor_sync(0xffffffff, state.count, offset)
        };
        state = merge(state, peer);
    }
    // warp 内所有线程最终持有整个 warp 的完整统计量

  对比两次分离归约（先 mean 后 var）：
    分离归约：读两遍全局内存，两次 __syncthreads()
    Welford ：读一遍全局内存，一次归约同时得到 mean 和 M2，节省约 33% 带宽

--------------------------------------------------------------------------------
三、CUDA 实现解析
--------------------------------------------------------------------------------

3.1 并行化策略
--------------
输入张量维度：[N, H]，N 为独立样本数（batch × sequence），H 为归一化维度。

  - 每个 CUDA block 负责处理一行（一个样本）。
  - 同一 block 内的多个线程协作对长度 H 的向量做归约（均值、方差）。
  - 线程数（block size）通常取 128~1024，H 较大时每个线程处理多个元素。

典型的 grid/block 配置：
    dim3 grid(N);             // 每个样本一个 block
    dim3 block(BLOCK_SIZE);   // BLOCK_SIZE = 256 或 512

3.2 并行归约（Parallel Reduction）
------------------------------------
计算均值 μ 和方差 σ² 均需全局求和，使用共享内存（shared memory）树形归约：

  Step 1: 每个线程将局部元素累加到寄存器。
  Step 2: 将寄存器值写入 shared memory。
  Step 3: __syncthreads() 后，逐步折半合并（stride = blockDim.x/2, /4, ...）。
  Step 4: 线程 0 持有最终结果，广播给 block 内所有线程（或直接用于下一步）。

Warp-level 优化：最后 32 个线程在同一 warp 内，可用 __shfl_down_sync() 代替
shared memory 归约，减少同步开销。

  // warp reduce 示例
  for (int offset = 16; offset > 0; offset >>= 1)
      val += __shfl_down_sync(0xffffffff, val, offset);

3.3 前向核函数结构（Forward Kernel）
--------------------------------------
  __global__ void layer_norm_forward(
      const float* __restrict__ x,      // [N, H]
      const float* __restrict__ gamma,  // [H]
      const float* __restrict__ beta,   // [H]
      float* __restrict__ y,            // [N, H]
      float* __restrict__ mean,         // [N]  供反向使用
      float* __restrict__ rstd,         // [N]  供反向使用
      int N, int H, float eps)
  {
      int row = blockIdx.x;             // 当前处理的样本
      const float* x_row = x + row * H;
      float* y_row = y + row * H;

      // Step 1: 计算均值（并行归约）
      float sum = 0.f;
      for (int i = threadIdx.x; i < H; i += blockDim.x)
          sum += x_row[i];
      // ... block reduce sum -> mu

      // Step 2: 计算方差（并行归约）
      float var = 0.f;
      for (int i = threadIdx.x; i < H; i += blockDim.x) {
          float diff = x_row[i] - mu;
          var += diff * diff;
      }
      // ... block reduce var -> sigma2
      float inv_std = rsqrtf(sigma2 / H + eps);   // rstd

      // Step 3: 写回统计量（供反向使用）
      if (threadIdx.x == 0) {
          mean[row] = mu;
          rstd[row] = inv_std;
      }

      // Step 4: 归一化 + 仿射变换
      for (int i = threadIdx.x; i < H; i += blockDim.x)
          y_row[i] = gamma[i] * ((x_row[i] - mu) * inv_std) + beta[i];
  }

3.4 反向核函数结构（Backward Kernel）
---------------------------------------
反向需要 x（或 x̂）、mean、rstd 以及上游梯度 dy。

  __global__ void layer_norm_backward(
      const float* dy,     // [N, H]  上游梯度
      const float* x,      // [N, H]  前向输入
      const float* gamma,  // [H]
      const float* mean,   // [N]
      const float* rstd,   // [N]
      float* dx,           // [N, H]  输入梯度
      float* dgamma,       // [H]     参数梯度（需原子加或分块归约）
      float* dbeta,        // [H]
      int N, int H)
  {
      int row = blockIdx.x;
      float mu  = mean[row];
      float inv = rstd[row];

      // 计算 c̄ = Σ(dy·γ), d̄ = Σ(dy·γ·x̂)
      float c_bar = 0.f, d_bar = 0.f;
      for (int i = threadIdx.x; i < H; i += blockDim.x) {
          float a  = dy[row*H+i] * gamma[i];
          float xh = (x[row*H+i] - mu) * inv;   // x̂ᵢ
          c_bar += a;
          d_bar += a * xh;
      }
      // ... block reduce c_bar, d_bar

      // 计算 dx
      float inv_H = 1.f / H;
      for (int i = threadIdx.x; i < H; i += blockDim.x) {
          float a  = dy[row*H+i] * gamma[i];
          float xh = (x[row*H+i] - mu) * inv;
          dx[row*H+i] = inv * (a - inv_H * c_bar - xh * inv_H * d_bar);
      }

      // dgamma, dbeta 需跨 row 累加，通常用 atomicAdd 或单独的归约核
  }

3.5 关键优化技巧
----------------
  a) 内存访问合并（Coalesced Access）
     - 按行分配给 block，同一 warp 的线程访问连续内存地址，满足合并访问要求。

  b) 向量化加载（Vectorized Load）
     - 使用 float4 / __half2 一次加载 4 个/2 个元素，提升内存带宽利用率。
       float4 val = reinterpret_cast<const float4*>(x_row)[i/4];

  c) Warp Shuffle 代替 Shared Memory 归约
     - 对最后一个 warp 的归约使用 __shfl_down_sync，避免 shared memory bank 冲突。

  d) 融合核（Fused Kernel）
     - 将前向的均值计算、方差计算、归一化、仿射变换合并在一个 kernel 中，
       减少全局内存读写次数（原本需要 3 遍扫描，融合后仅需 2 遍）。

  e) 混合精度（Mixed Precision）
     - 输入/输出可使用 half（FP16）或 bfloat16，统计量累加使用 float32，
       兼顾性能与数值精度。

  f) 持久化线程（Persistent Threads）/ CUB 库
     - 对于 H 极大（>65536）的情况，可借助 CUB::BlockReduce 或 CUB::DeviceReduce
       获得更优的归约性能。

3.6 参数梯度 dgamma / dbeta 的并行策略
----------------------------------------
dgamma[i] = Σ_{row=0}^{N-1} dy[row, i] · x̂[row, i]
dbeta[i]  = Σ_{row=0}^{N-1} dy[row, i]

两者需对 N 个样本求和，有两种实现方式：

  方案 A：原子加（atomicAdd）
    - 每个 block 处理一行，对共享的 dgamma/dbeta 做 atomicAdd。
    - 实现简单，但 N 较大时原子冲突严重，性能差。

  方案 B：二阶段归约
    - 第一阶段：每个 block 计算本行对 dgamma/dbeta 的贡献，写入临时缓冲区
      temp[N, H]。
    - 第二阶段：对 N 维做列归约，得到最终结果。
    - 访问模式更规则，适合大 batch 场景。

--------------------------------------------------------------------------------
五、与 Batch Normalization 的对比
--------------------------------------------------------------------------------

5.1 归一化维度的本质区别
--------------------------

统计量形状由 normalized_shape（归一化维度）决定，不同场景如下：

── CNN 场景：输入 [N, C, H, W] ──────────────────────────────────────────────

  BatchNorm：normalized_shape = [N, H, W]（对每个 C，跨 N、H、W 统计）
    μ_c = (1/(N·H·W)) · Σ_{n,h,w} x[n,c,h,w]
    统计量形状：[1, C, 1, 1]  ← 每个通道一个均值/方差
    含义：同一卷积核（channel）在不同样本、不同位置的激活值服从相似分布，
          跨样本统计是有意义的

  LayerNorm（CNN）：normalized_shape = [C, H, W]（对每个 N，跨 C、H、W 统计）
    μ_n = (1/(C·H·W)) · Σ_{c,h,w} x[n,c,h,w]
    统计量形状：[N, 1, 1, 1]  ← 每个样本一个均值/方差

── NLP 场景：输入 [N, T, D] ─────────────────────────────────────────────────
  N = batch size，T = seq_len（token 数），D = embedding dim

  LayerNorm（NLP）：normalized_shape = [D]（对每个 token，仅在 D 上统计）
    μ_{n,t} = (1/D) · Σ_d x[n,t,d]
    统计量形状：[N, T, 1]  ← 每个 token 各有一个独立的均值/方差
    含义：同一 token 的 D 维 embedding 是同一向量空间的坐标，
          在内部做归一化有意义；不同 token 之间语义无关，不跨 token 统计

直观示意（NLP，简化为 [N=1, T=3, D=4]）：

  token0  [x x x x]   ← LayerNorm 在这 D=4 个值上统计 → 1 个 μ, 1 个 σ²
  token1  [x x x x]   ← LayerNorm 在这 D=4 个值上统计 → 1 个 μ, 1 个 σ²
  token2  [x x x x]   ← LayerNorm 在这 D=4 个值上统计 → 1 个 μ, 1 个 σ²
  统计量形状：[1, 3, 1] = [N, T, 1]，共 3 个均值/方差

  对比 BatchNorm（若强行用于 NLP）：
  token0  [x x x x]
  token1  [x x x x]
          ↑ ↑ ↑ ↑
  跨 token 统计同一 embedding 维度——"第 5 维在不同 token 上的分布"
  语义上无意义（不同 token 代表完全不同的词）

5.2 训练与推理的统计量处理
----------------------------

  BatchNorm：
    - 训练阶段：用当前 mini-batch 的实时统计量做归一化，
      同时以指数滑动平均（EMA）维护全局 running_mean 和 running_var。
    - 推理阶段：不再计算 batch 统计量，直接使用训练积累的 running_mean/var。
    - 问题：batch size 越小，实时统计量越不稳定，方差估计越不准确。

  LayerNorm：
    - 训练和推理阶段：每次都对当前样本实时计算均值和方差。
    - 不依赖 batch 内其他样本，也不需要维护任何全局统计量。
    - 训练/推理行为完全一致，没有 train/eval 模式差异。

5.3 全面对比
--------------

  维度              BatchNorm                     LayerNorm
  ───────────────────────────────────────────────────────────────────
  统计量计算维度    跨样本 N（每通道独立）         跨特征维度（每样本/token 独立）
  统计量形状        [1, C, 1, 1]                   CNN:[N,1,1,1] / NLP:[N,T,1]
  依赖 batch size   是（小 batch 不稳定）           否
  推理时统计量      使用预存 running mean/var       实时计算，无需预存
  train/eval 差异   有（行为不同）                  无（完全一致）
  序列变长支持      差（不同长度的 batch 统计混乱） 好（每样本独立）
  参数共享方式      γ/β 按通道共享 [1, C, 1, 1]    γ/β 按特征共享 [C]
  计算开销          推理开销小（统计量已预存）       每次实时计算
  内存开销          需额外存 running_mean/var        无额外存储

5.4 应用场景
--------------

  BatchNorm 适用场景：
    - CNN 图像模型（ResNet、VGG、EfficientNet 等）
      原因：图像 batch 通常 ≥ 32，跨样本统计可靠；
            卷积特征图具有空间平稳性，同通道不同位置的特征分布相似，
            适合在 N,H,W 上统一统计。
    - 训练样本充足、batch size 较大（≥ 16）的场景。
    - 需要隐式正则化效果（batch 内统计量的随机性有类似 Dropout 的效果）。

  LayerNorm 适用场景：
    - Transformer / 自注意力模型（BERT、GPT、ViT 等）
      原因：序列长度可变，不同样本长度不同，batch 内统计跨样本无意义；
            每个 token 的 embedding 维度归一化更符合语义独立性假设。
    - RNN / LSTM
      原因：循环网络时间步方向不固定，batch 统计在时序上不稳定。
    - 小 batch 或 batch size = 1（在线学习、生成式推理）。
    - 强化学习：每次只有一个或少量样本交互。
    - 多模态、图神经网络等批次结构不规则的场景。

5.5 其他归一化变体（拓展）
----------------------------

  InstanceNorm：对每个 (N, C)，在 H, W 上统计
    统计量形状：[N, C, 1, 1]
    适用：风格迁移（style transfer），每张图每通道独立归一化保留风格信息。

  GroupNorm：将 C 维分为 G 组，每组内在 (C/G, H, W) 上统计
    统计量形状：[N, G, 1, 1]
    适用：batch size 小但通道数多的场景，如目标检测（batch=1~2）。
    特例：G=1 退化为 LayerNorm；G=C 退化为 InstanceNorm。

  RMSNorm（Root Mean Square LayerNorm）：
    去掉均值中心化步骤，只做方差归一化：
      ȳ = x / sqrt((1/H)·Σxᵢ² + ε)   再乘以 γ（无 β）
    适用：LLaMA、T5 等现代 LLM，计算量比 LayerNorm 减少约 7%，
          实验表明效果相当。

六、关键设计问题解析
--------------------------------------------------------------------------------

6.1 每个 token 为何需要独立的 mean 和 var？
--------------------------------------------
LayerNorm 在 NLP 场景中的归一化维度是 D（embedding dim），统计量形状为 [N, T, 1]：

  token_0  [x x x x x x x x]  → 独立计算 μ₀, σ₀²
  token_1  [x x x x x x x x]  → 独立计算 μ₁, σ₁²
  token_2  [x x x x x x x x]  → 独立计算 μ₂, σ₂²

原因：每个 token 的 D 维 embedding 是该 token 在语义向量空间中的坐标，是一个
独立的语义单元。不同 token 表示完全不同的词或子词，它们的激活值之间没有统计
关联性，跨 token 做统计（如 BatchNorm 跨样本统计）在语义上是无意义的。

对应到实现：输入矩阵 [N×T, D] 中每一行是一个独立的归一化单元，
CUDA kernel 中 grid 的 y 维对应行数（N×T），每个 block/线程组负责一整行。

6.2 训练与推理时 mean/rstd 的差异
----------------------------------
LayerNorm 的 mean/rstd 在训练和推理时均从当前输入实时计算（与 BatchNorm 不同，
BatchNorm 推理时使用预存的 running_mean/var）。两者的本质差异在于是否需要保存：

  训练阶段（前向 + 反向）：
    - 前向：实时计算 mean/rstd，并写入全局内存缓冲区保存
    - 反向：从缓冲区读取 mean/rstd，重建 x̂ = (x - mean) * rstd，计算 dx
    - 反向传播公式：dx = rstd · [ dy·γ − (1/H)·Σ(dy·γ) − x̂·(1/H)·Σ(dy·γ·x̂) ]
      其中 x̂ 依赖前向保存的 mean 和 rstd，若不保存则无法正确计算梯度

  推理阶段（仅前向）：
    - 实时计算 mean/rstd，用于完成归一化后立即丢弃
    - 不需要分配 mean/rstd 输出缓冲区，节省显存和全局内存写带宽
    - 推理 kernel 通常将 mean/rstd 参数设为 nullptr 或完全省去

  对比表：
    阶段      计算方式          是否保存 mean/rstd    原因
    ───────────────────────────────────────────────────────
    训练      实时计算          必须保存              反向传播重建 x̂ 时需要
    推理      实时计算          无需保存              没有反向传播，用完即丢

6.3 weight/bias 为何按列（特征维度）索引，而不是按行（样本）索引？
------------------------------------------------------------------
LayerNorm 的仿射变换公式为：

    y[n, i] = γ[i] · x̂[n, i] + β[i]

γ 和 β 的下标是 i（特征维度），不是 n（样本），原因如下：

  1. γ/β 是"特征属性"，不是"样本属性"
     归一化后每行均值=0、方差=1，原始分布信息被抹平。γ[i] 的作用是恢复第 i 个
     特征维度"应有的表达范围"——某个 hidden dim 在语义上需要更大的激活幅度，
     则令 γ[i] 更大。这是特征维度的属性，与具体是哪条样本无关。

  2. 跨样本共享，才能泛化到新样本
     若改为 weight[row]，则每条样本持有独立的 γ，推理时遇到新样本根本没有对应
     参数。weight[col] 让模型学到"第 i 维的缩放规律"，对所有样本通用，
     参数量 = D（特征维度大小），与 batch size / seq_len 无关。

  3. 与 BatchNorm 一致
     BN 的 γ/β 同样是 per-channel（per-feature），不是 per-sample。
     原因相同：参数必须在样本间复用，编码的是特征维度的分布属性。

  对应到 CUDA 核函数：

    // 第 i 个特征，对任意 row 使用同一 weight[i] / bias[i]
    for (int i = threadIdx.x; i < H; i += blockDim.x)
        out[i] = weight[i] * (A[i] - rowMean) * rowVar + bias[i];
    //           ↑ 按特征维度索引                    ↑ 按特征维度索引

  若误写为 weight[row] / bias[row]，则对同一样本的所有特征施加同一个标量缩放，
  失去对各特征维度差异化处理的能力。
