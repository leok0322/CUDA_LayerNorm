  │  4096×512  │  17.0    │   49.3   │ +190%  │

--------------------------------------------------------------------------------
三、主要提升来源：SM 占用率（不是 SMEM 复用）
--------------------------------------------------------------------------------

3.1 Kernel 3 的低占用率问题
────────────────────────────
Kernel 3 的 block 固定为 1024 线程，一次处理 1 行（totalCol 个元素）。
每个线程的循环：

  for (col = threadIDX; col < totalCol / 4; col += 1024)

当 totalCol = 128 时，totalCol / 4 = 32 < 1024，
线程 32..1023（共 992 条）循环体一次也不执行，完全空转。
空转线程仍占据 warp 调度槽，SM 的 warp utilization 极低。

3.2 Kernel 6 的改进
──────────────────────
Kernel 6 的 block = (256, 4, 1)，同样 1024 线程，但同时处理 4 行。
当 totalCol = 128 时，每行由 256 线程处理，每线程负责 128/256 < 1 列，
仍然有空转，但 4 行合并后有效工作量是 kernel 3 的 4 倍。

本质上：kernel 6 让同等线程数承担更多行，提高了每个 warp 的有效执行比例，
SM 利用率随之提升。n 越小这个效应越显著，与 benchmark 数据完全吻合。

3.3 小 n 下的极端提升
─────────────────────
  n=128 时：kernel 3 中 1024 线程仅 128/4=32 条有效，利用率 ~3%
            kernel 6 中 256×4 线程覆盖 4 行共 128 列，利用率 ~12.5%（仍低，但高 4×）
  n=1024 时：kernel 3 中 1024 线程恰好满覆盖（每线程 1 列），利用率较好
             kernel 6 中 256 线程覆盖 1024/4=256 列，每线程 4 列，利用率与 kernel 3 相当
             → n 越大，SM 占用率这一优势逐渐消失。

--------------------------------------------------------------------------------
四、SMEM 复用 weight/bias 的实际收益
--------------------------------------------------------------------------------

4.1 设计意图
──────────────
Kernel 6 在同一 block 内处理 4 行时，只由 threadIdx.y==0 的行从 GMEM 加载
weight 和 bias 到 SMEM，其余 3 行直接读 SMEM：

  写（仅一次 GMEM 访问）：
    if (threadIdx.y == 0) smemWeight[col][0..3] = weight[col*4..col*4+3];

  读（4 行均使用，仅 SMEM 访问）：
    vecA.x = smemWeight[col][0] * ...

理论上每 4 行共用 1 次 GMEM 加载，weight/bias 的 GMEM 流量减少 4 倍。

4.2 实际收益为何有限
──────────────────────
Kernel 3 中，weight/bias 被所有 totalRow 个 block 按列顺序读取，
访问模式规律，很快全部进入 L2 cache（或 L1）：

  weight 大小 = totalCol × 4 字节（n=4096 → 16 KB，fits in L1 64 KB）

  → 第 1 个 block 后，后续所有 block 读 weight/bias 均命中 L2/L1，
    有效带宽接近 SMEM 带宽，SMEM 复用相对于 L2 命中的优势不大。

因此，"SMEM 复用减少 GMEM 访问" 在实际中并未带来显著提升，
benchmark 显示的性能差距主要来自 SM 占用率的改善，而非 weight/bias 复用。

注：kernel 6 代码中已有注释："smemWeight、smemBias没有任何复用，
GMEM加载没有少，反而多了一次从SMEM加载的开销。"这描述的是单行视角——
从每行自身来看确实多了一次 SMEM 搬运；但跨行视角下 4 行共用 1 次 GMEM
加载，有一定的 L2 带宽节省，只是效果不如预期显著。

--------------------------------------------------------------------------------
五、n=4096 时 Kernel 6 反而更慢的原因
--------------------------------------------------------------------------------

5.1 SMEM 占用过高限制 occupancy
─────────────────────────────────
Kernel 6 每个 block 的静态 SMEM：

  smemWeight[1024][5]            = 1024 × 5 × 4 = 20 KB
  smemBias[1024][5]              = 1024 × 5 × 4 = 20 KB
  reduction[BLOCK_SIZE_Y_SMEM][32] = 4 × 32 × 4 =  0.5 KB
  ─────────────────────────────────────────────────────
  合计                                              40.5 KB

Ampere SM（如 RTX 3090）的默认 SMEM 上限为 48 KB/block。
40.5 KB 接近上限，导致：

  每个 SM 可同时驻留的 block 数 = floor(48 KB / 40.5 KB) = 1
  threads/SM = 1 × 1024 = 1024（Ampere 最大 2048）→ occupancy = 50%

Kernel 3 的 SMEM 仅 128 字节，每 SM 可驻留多个 block，warp 调度更灵活。

5.2 n=4096 时 Kernel 3 已接近满载
───────────────────────────────────
n=4096 时 1024 线程恰好以 4 个 col/thread（每次处理 4 个 float）覆盖全行，
没有空转线程，kernel 3 的 SM 利用率已经很高。
此时 kernel 6 的 SMEM 带来的 occupancy 损失完全抵消了多行处理的优势，
整体性能反而下降约 32%。

六、Autotune 结果（BLOCK_SIZE_X_SMEM × BLOCK_SIZE_Y_SMEM 网格搜索）
--------------------------------------------------------------------------------

对 BLOCK_SIZE_X_SMEM ∈ {32,64,128,256,512,1024}、BLOCK_SIZE_Y_SMEM ∈ {1,2,4,8,16,32}
（约束 BSX×BSY ≤ 1024）共 21 种组合做全量搜索，选三个代表性 size 观察：

  ┌────────────┬──────────────┬────────────┬────────────┬────────────┐
  │ BSX   BSY  │ 总线程数     │ 1024×1024  │ 4096×1024  │ 4096×4096  │
  ├────────────┼──────────────┼────────────┼────────────┼────────────┤
  │  32 ×  1   │    32        │   21.3     │   22.2     │   20.7     │
  │  32 ×  4   │   128        │   42.6     │   49.8     │   31.6     │
  │  64 ×  4   │   256        │   47.5     │   59.9     │   32.2  ↓  │
  │ 128 ×  2   │   256        │   51.7     │   62.5     │   40.0  ↓  │
  │ 128 ×  8   │  1024        │   55.2     │   60.7     │   31.3  ↓  │
  │ 256 ×  1   │   256        │   51.9     │   59.1     │   58.3  ✓  │
  │ 256 ×  2   │   512        │   57.7     │   58.2     │   36.6  ↓  │
  │ 256 ×  4   │  1024（默认）│   54.1     │   61.4     │   42.0  ↓  │
  │ 512 ×  1   │   512        │   48.9     │   55.3     │   54.9  ✓  │
  │ 512 ×  2   │  1024        │   44.6     │   51.1     │   59.6  ✓  │
  │1024 ×  1   │  1024        │   31.7     │   32.1     │   61.4  ✓  │
  └────────────┴──────────────┴────────────┴────────────┴────────────┘

规律：
  - BSY ≥ 2 的配置在 n=4096 时普遍大幅下跌（30~42 GFLOPS）
  - BSY = 1 的配置在所有 size 下表现稳定（无大跌）
  - BSX=256, BSY=1 是综合最稳定的配置，三个 size 均保持 51~59 GFLOPS

--------------------------------------------------------------------------------
七、BSY=1 揭示的设计问题：SMEM 复用完全无效
--------------------------------------------------------------------------------

BSY=1 时每个 block 只处理 1 行，weight/bias 的 SMEM 流程退化为：

  GMEM → SMEM（加载一次）→ 寄存器（同一行内使用一次）

加载一次、使用一次，跨行复用为零。与直接读 GMEM（命中 L2）相比：
  - GMEM 访问量没有减少（仍需读一次 weight/bias）
  - 多了一次 SMEM 搬运开销
  - smemWeight + smemBias 占用 40 KB 静态 SMEM，限制每 SM 只能驻留 1 个 block

BSY=1 是最优配置这一事实说明：**kernel 6 的 SMEM 复用设计在实际测试中没有带来净收益**，
反而因为 40 KB 的静态 SMEM 压低了 occupancy，在大 n 时拖累性能。

--------------------------------------------------------------------------------
八、结论与改进方向
--------------------------------------------------------------------------------

  ┌──────────────────────────────────┬─────────────────────────────────────────┐
  │ 性能因素                          │ 实际效果                               │
  ├──────────────────────────────────┼─────────────────────────────────────────┤
  │ 多行 block → SM 占用率提升        │ 主要收益，但 BSY=1 下完全消失          │
  ├──────────────────────────────────┼─────────────────────────────────────────┤
  │ weight/bias SMEM 复用            │ 无实际收益，BSY=1 时反而增加开销       │
  ├──────────────────────────────────┼─────────────────────────────────────────┤
  │ SMEM 体积大（40.5 KB）           │ 负面影响，所有配置下都限制 occupancy   │
  ├──────────────────────────────────┼─────────────────────────────────────────┤
  │ BSX 从 1024 降至 256/512         │ 真正有效的改进：减少小 n 时的空转线程  │
  └──────────────────────────────────┴─────────────────────────────────────────┘

  kernel 6 相对于 kernel 3 的真实改进只有一条：
    BSX 从固定 1024 变为可调的 256/512，减少小 n 时的空转线程。
  SMEM 复用是无效设计，应当去掉。

  理想的改进方向（"BSX 可调的 kernel 5"）：
    - 1 个 block 处理 1 行（BSY = 1，不做多行）
    - 不缓存 weight/bias 到 SMEM（直接读 GMEM，L2 命中即可）
    - SMEM 仅保留 reduction 数组（~128 字节）
    - BSX = 256 或 512（而非 1024），避免小 n 空转，同时保持 occupancy
