================================================================================
  CUDA 内联 PTX：asm volatile 语法详解
  ── 以 load128cs / store128cs 为例
================================================================================

--------------------------------------------------------------------------------
一、背景：为什么需要内联 PTX
--------------------------------------------------------------------------------

  CUDA C++ 编译器（nvcc）生成的指令默认经过 L1 cache。
  对于"写一次即丢弃"的数据（如 LayerNorm 的 output）或"读一次即不复用"的数据
  （如矩阵 A 的每行元素），长期占用 L1 会挤占 weight/bias 等高复用数据的缓存空间。

  PTX 提供 cache streaming hint（.cs 修饰符）：
    ld.global.cs   加载后数据在 L1 快速逐出，避免污染 L1
    st.global.cs   写入后数据在 L1 快速逐出，减少写回占用

  CUDA C++ 没有直接暴露 .cs 的高层语法，必须通过内联 PTX（asm volatile）调用。

  load128cs / store128cs 是封装了上述 PTX 指令的 C++ helper 函数，定义于 common.cuh。

--------------------------------------------------------------------------------
二、asm volatile 语法结构
--------------------------------------------------------------------------------

  asm volatile(
      "PTX指令字符串"          // 1. 要执行的 PTX 指令，操作数用 %0、%1... 占位
      : 输出操作数列表          // 2. C++ 变量 ← PTX 寄存器（被写入的变量）
      : 输入操作数列表          // 3. PTX 寄存器 ← C++ 变量（只读的变量）
  );

  volatile 的作用：
    禁止编译器对该 asm 块做重排或消除（即使输出值在后续代码中未被使用）。
    对于有副作用的指令（store、带 hint 的 load）必须加 volatile，
    否则编译器可能判断"结果未使用"而删除整个 asm 块。

  操作数约束字符串（constraint string）：
    "=f"   写入（=）、绑定到 float 寄存器（f）        → 用于输出操作数
    "f"    只读、绑定到 float 寄存器（f）              → 用于输入操作数
    "l"    只读、绑定到 64-bit 整数寄存器（l = long）  → 用于指针操作数

  占位符编号规则：
    输出操作数从 %0 开始连续编号；
    输入操作数紧接输出操作数之后继续编号。

--------------------------------------------------------------------------------
三、load128cs 解析
--------------------------------------------------------------------------------

  函数签名：
    __device__ inline x128 load128cs(const float* addr)

  PTX 指令：ld.global.cs.v4.f32 {dst0, dst1, dst2, dst3}, [src]
    ld       ：load（从内存读取到寄存器）
    global   ：地址空间为全局内存（cudaMalloc / __device__ 变量）
    cs       ：cache streaming hint，加载后数据在 L1 快速逐出
    v4.f32   ：向量宽度 4，元素类型 float，单次传输 4×4 = 16 字节（128-bit）
    {%0..%3} ：4 个目标寄存器，写入 4 个 float
    [%4]     ：源地址寄存器（64-bit 指针）

  完整 asm 语句：

    asm volatile("ld.global.cs.v4.f32 {%0,%1,%2,%3}, [%4];"
                 : "=f"(x.data[0]),   // %0 输出：写入 x.data[0]，float 寄存器
                   "=f"(x.data[1]),   // %1 输出：写入 x.data[1]
                   "=f"(x.data[2]),   // %2 输出：写入 x.data[2]
                   "=f"(x.data[3])    // %3 输出：写入 x.data[3]
                 : "l"(addr));        // %4 输入：读取 addr，64-bit 指针寄存器

  操作数映射：
    %0 → x.data[0]    (=f，输出)
    %1 → x.data[1]    (=f，输出)
    %2 → x.data[2]    (=f，输出)
    %3 → x.data[3]    (=f，输出)
    %4 → addr         ( l，输入，指针)

  等价的普通加载（无 .cs hint，经 L1 cache）：
    *reinterpret_cast<float4*>(x.data) = *reinterpret_cast<const float4*>(addr);

--------------------------------------------------------------------------------
四、store128cs 解析
--------------------------------------------------------------------------------

  函数签名：
    __device__ inline void store128cs(float* addr, x128 val)

  PTX 指令：st.global.cs.v4.f32 [dst], {src0, src1, src2, src3}
    st       ：store（从寄存器写入内存）
    global   ：目标地址空间为全局内存
    cs       ：cache streaming hint，写入后数据在 L1 快速逐出
    v4.f32   ：一次写 4×float = 128-bit
    [%0]     ：目标地址寄存器（64-bit 指针）
    {%1..%4} ：4 个源寄存器，依次写入 4 个 float

  完整 asm 语句：

    asm volatile("st.global.cs.v4.f32 [%0], {%1,%2,%3,%4};"
                 :                          // 输出操作数为空（store 无 C++ 侧输出变量）
                 : "l"(addr),               // %0 输入：目标地址，64-bit 指针寄存器
                   "f"(val.data[0]),        // %1 输入：写入值，float 寄存器
                   "f"(val.data[1]),        // %2 输入
                   "f"(val.data[2]),        // %3 输入
                   "f"(val.data[3]));       // %4 输入

  操作数映射：
    %0 → addr          ( l，输入，指针)
    %1 → val.data[0]   ( f，输入)
    %2 → val.data[1]   ( f，输入)
    %3 → val.data[2]   ( f，输入)
    %4 → val.data[3]   ( f，输入)

  输出操作数为空，两个冒号紧邻（": :"）：
    store 指令没有"写回 C++ 变量"的需求，输出段留空。
    volatile 必须保留：输出为空时编译器无法通过数据流分析判断副作用，
    若不加 volatile，整个 asm 块可能被优化删除。

--------------------------------------------------------------------------------
五、load128cs vs load128 对比
--------------------------------------------------------------------------------

  ┌─────────────────┬──────────────────────────────┬──────────────────────────────┐
  │                 │ load128                      │ load128cs                    │
  ├─────────────────┼──────────────────────────────┼──────────────────────────────┤
  │ PTX 指令        │ （编译器自动生成）             │ ld.global.cs.v4.f32          │
  │ L1 行为         │ 数据进入 L1，可复用            │ 加载后快速逐出 L1            │
  │ 适用数据        │ weight/bias（多行共用，高复用） │ A（每行读一次，不复用）       │
  │ 实现方式        │ C++ reinterpret_cast float4   │ asm volatile 内联 PTX        │
  └─────────────────┴──────────────────────────────┴──────────────────────────────┘

  store128cs 对应场景：output（写一次即完成，不应长占 L1）。

--------------------------------------------------------------------------------
六、约束字符速查
--------------------------------------------------------------------------------

  常用约束字符（NVPTX / GCC 扩展内联汇编）：
    =     写入（output 操作数专用前缀）
    f     float 寄存器（32-bit 浮点）
    d     double 寄存器（64-bit 浮点）
    r     32-bit 整数寄存器
    l     64-bit 整数寄存器（常用于指针）
    h     16-bit 整数寄存器

  占位符编号：
    输出操作数优先编号（%0、%1...），输入操作数紧接其后继续编号。
    输出为空（store 场景）时，输入从 %0 开始编号。
